# 标点符号、混排留白与文本格式（Punctuation and Formatting）

涵盖中英文混排空格（盘古之白）、全角与半角标点符号、专有名词大小写、粗体/斜体/代码字体选用及各类标点的具体用法。

## 中英文混排留白规范（盘古之白）

在中文技术文档中，合理的留白能显著提升可读性：

- **必须加一个半角空格的场景**：
  - 中文与英文字母之间：“在 macOS 上部署 Node.js 应用”。
  - 中文与阿拉伯数字之间：“创建 3 个副本”“等待 10 秒”。
  - 中文与行内代码（`` `code` ``）之间：“运行 `kubectl get pods` 命令查看状态”。
  - 数字与英文单位缩写之间：“分配 64 GB 内存”“延迟低于 25 ms”（优先使用不换行空格或普通半角空格，绝不连写成 `64GB`）。
- **绝不加空格的场景**：
  - 中文字符与**中文全角标点**之间，以及**中文全角标点**与英文/数字/行内代码之间：“请打开 `config.yaml`，然后将端口改为 8080。”（注意逗号与 `config.yaml` 之间无空格）。
  - 数字与百分号、角度符号、货币符号之间：`85%`、`180°`、`$10`、`¥100`。
  - 斜杠（`/`）表示路径或并列关系时两侧不加空格：`TCP/IP`、`/etc/hosts`。

| 推荐写法 | 不推荐写法 |
|---|---|
| “使用 `gcloud` CLI 初始化项目，并配置 2 个可用区。” | “使用`gcloud`CLI初始化项目，并配置2个可用区。” |
| “支持 JSON、YAML 和 TOML 格式。” | “支持 JSON 、 YAML 和 TOML 格式。”（全角标点旁误加空格） |
| “内存上限为 16 GB，CPU 使用率不超过 80%。” | “内存上限为 16GB，CPU 使用率不超过 80 %。” |

## 专有名词与大小写规范

虽然汉字没有大小写之分，但中文技术文档中包含大量英文专有名词、缩略语、标题和代码标识符：

- **严格遵循品牌与技术的官方大小写**：
  - 常见易错词：`GitHub`、`GitLab`、`macOS`、`iOS`、`iPadOS`、`JavaScript`、`TypeScript`、`Node.js`、`PostgreSQL`、`MySQL`、`MongoDB`、`Redis`、`Kubernetes`、`Docker`、`GraphQL`、`gRPC`、`OAuth 2.0`、`WebSocket`、`Wi-Fi`、`YouTube`。
  - 官方定为全小写的命令或项目名（如 `curl`、`git`、`npm`、`tmux`），在正文中也应保持全小写（或放入反引号中：`` `curl` ``），切勿因为处于句首就强行写成 `Curl` 或 `Git`（指代命令时）。
- **文档标题与章节标题中的英文采用 Sentence case（首字母大写）**：当中文标题中包含英文词组时，除专有名词和固定全大写缩写（如 `API`、`SDK`、`HTTP`）外，普通英文单词无需每个首字母都大写。
- **不靠大小写区分含义**：不要在正文中仅凭首字母大小写来区分概念（例如在 Kubernetes 文档中，如果同时用 `Pod` 和 `pod` 表达不同含义，读者极易混淆，应加上明确的中文定语如“`Pod` 对象”）。
- **占位符一律使用全大写加下划线（`UPPER_SNAKE_CASE`）**：如 `PROJECT_ID`、`API_KEY`（详见 `code-and-ui.md`）。

## 文本样式选用规则（粗体、斜体、代码字体）

| 文本样式 | 适用场景 |
|---|---|
| **粗体（`**文本**`）** | 1. **UI 界面元素名称**（按钮、菜单、对话框、标签页、输入框名称，如“点击**保存**”）。<br>2. **列表项的引导词/术语头**（如 `- **超时时间**：请求等待的最大秒数。`）。<br>3. **提示框标签**（如 **注意**、**重要**、**警告**）及极少数需要强烈强调的核心关键字。 |
| `代码字体`（`` `code` ``） | 凡是需要**原样输入**或属于程序字面量的内容：命令行指令、文件名、路径、环境变量、类名、方法名、参数名、布尔值（`true`/`false`）、HTTP 状态码及动词（`POST`）、占位符。详见 `code-and-ui.md`。 |
| *斜体（`*文本*`）* | **中文正文禁用斜体！** 汉字使用斜体（伪斜体）在小字号屏幕下极难辨认且破坏版面美观。在中文文档中：需强调重点请用**粗体**；指代书名、文章名、规范名请用书名号**《》**；指代特定词汇本身请用双引号**“”**。仅在**纯英文数学变量**（如 *x*、*y*）或版本号通配符（如 `1.4.`*`x`*）中可使用斜体。 |
| 链接下划线 | 仅用于超链接文本（Markdown 链接 `[锚文本](URL)`），切勿用 HTML `<u>` 给普通文字加下划线。 |
| 普通正文 | 其余所有内容。 |

- **`&` 符号（Ampersand）**：在中文正文、标题和导航栏中，切勿用 `&` 代替“和 / 与”。仅当 UI 界面原本就写着 `&`（如 `**APIs & Services**`）或在代码语法中才使用 `&`。

## 全角与半角标点符号全解

**基本铁律**：中文语境下使用**全角中文标点**；代码块、命令行、URL 内部使用**半角英文标点**。

### 1. 句号（` http://...` 除外，一律用 `。`）
- 中文陈述句末尾使用全角句号 `。`。
- **所有级别的标题（`#` ~ `######`）末尾绝不加句号**。
- 当句末刚好是 URL 时，为防止读者复制 URL 时误把句号复制进去，尽量将 URL 放进 Markdown 链接 `[描述文本](URL)` 中，或将 URL 单独成行。

### 2. 逗号（`，`）与顿号（`、`）
- **逗号（`，`）**：用于分隔句子内部的分句，或带较长修饰语的并列短语。
- **顿号（`、`）**：中文特有标点，专门用于分隔句子内部**并列的词语或短语**（即使是英文单词并列，只要处于中文句子中，也用全角顿号分隔，且顿号两侧不加空格）：
  - 推荐：“支持 `Linux`、`macOS` 和 `Windows` 操作系统。”
  - 不推荐：“支持 `Linux`, `macOS`, 和 `Windows` 操作系统。”
- 最后一个并列项之前，可视语感使用“和 / 与 / 或”连接（此时前面不加顿号）。

### 3. 冒号（`：`）
- 用于引导列表、代码块、表格或提示说明。
- **引导列表或代码块的前导句必须是一个语义完整的句子**：“该配置包含以下字段：”而不是残缺的“该配置包含有：”。
- 在描述列表（键值对说明）中，术语与解释之间使用全角冒号 `：`（如 `- **地域（Region）**：数据中心所在的物理位置。`），不要用破折号或连字符代替冒号。

### 4. 分号（`；`）
- 尽量少用分号，长句优先拆成两个独立句子或改用无序列表。
- 仅在并列分句内部已经使用了逗号、需要更高一级的分隔层级时，才使用全角分号 `；`。

### 5. 引号（`“”` 与 `‘’`）
- **中文正文中使用弯引号（全角双引号 `“”`）**，嵌套引号使用全角单引号 `‘’`。
- **代码块与命令行中必须使用英文直引号（`""` 和 `''`）**：因为代码解析器不识别全角弯引号。
- **不要给已经加了反引号（`` `code` ``）的代码元素再套一层中文引号**：
  - 推荐：将 `status` 参数设为 `"active"`。
  - 不推荐：将“`status`”参数设为“`"active"`”。
- **引号内外的句末标点**：
  - 如果引号内是完整引用的一句话，句号放在右引号里面（如：系统提示：“连接已超时。”）。
  - 如果引号内只是一个词、短语或概念名称，句末标点放在右引号外面（如：这种机制称为“幂等性”。）。

### 6. 括号（`（）`）
- 中文正文中一律使用**全角圆括号 `（）`**，括号内外均**不加空格**（如“使用传输层安全协议（TLS）加密流量”）。
- 仅在代码块、函数名标识（如 `initializeApp()`）或纯英文句段中才使用半角括号 `()`。
- **别把核心关键信息藏在括号里**：读者浏览时常会跳过括号内容；如果括号里的说明很长，请直接拆成独立句子。
- **句号位置**：如果括号紧跟在某个词后面做局部补充说明，句号放在右括号外面；如果整个括号独立成句，句号放在右括号里面。

### 7. 书名号（`《》`）
- 用于标示书籍、法规、国家/行业标准、官方文档全称或长篇专栏标题（如《Google 开发者文档风格指南》《网络安全法》）。
- 如果文档标题本身已经作为超链接呈现（如 `[快速入门指南](url)`），则**无需再加书名号**，以免视觉杂乱。

### 8. 破折号（`——`）、连接号（`–` / `~`）与连字符（`-`）
- **中文破折号（`——`，占两个全角字符，即两个 `—`）**：用于解释说明或话题突然转折，两侧不加空格（如“你可以监控多项核心指标——例如 CPU 利用率、内存占用和活跃连接数。”）。切勿用单个连字符 `-` 或双连字符 `--` 冒充破折号。
- **范围连接号（`~` 或 `–`）**：在中文技术文档中，表示数值、版本或时间范围时，推荐使用波浪号 `~` 或一字线 `–`（如 `8~20 个文件`、`2022–2026 年`），或者直接用中文“至 / 到”（如“8 到 20 个文件”）。**切勿混用“从 A~B”**（应写“从 A 到 B”或直接写“A~B”）。当涉及负数范围时，必须用“至 / 到”（如 `-40 °C 至 85 °C`），以免连字符与负号混淆。
- **英文连字符（`-`，半角）**：仅用于英文复合词（如 `read-only`、`cloud-native`）、命令行标志（`--force`）及文件名（`my-config.yaml`）。

### 9. 叹号（`！`）与问号（`？`）
- **正文中严禁使用感叹号 `！`**：技术文档需要冷静、客观、可靠的语感，感叹号会让读者觉得轻浮或像是在对读者大喊大叫（唯一例外：代码中的非运算符 `!=`、日志字面量，或长篇新手教程最后一步的“恭喜！你已完成全部配置。”）。
- **问号 `？`**：可用于 FAQ（常见问题解答）样式的标题或排障引导问题。

### 10. 斜杠（`/`）
- 除文件路径（`/var/log`）、URL、协议名（`HTTP/2`、`TCP/IP`）和速率单位（如表格空间受限时的 `MB/s`）外，尽量少在正文中用 `/` 堆砌近义词（如把“创建/更新/删除资源”改写为“创建、更新或删除资源”）。
- **禁用“和/或（and/or）”**：写“A、B 或两者兼具”，或在语义不冲突时直接写“A 或 B”。
